## 00. 2026-11-01 修订：面向大陆普通用户

目标用户在中国大陆网络下，绝大多数只会下载、安装、打开、选线路、连接。以下决定优先于本文其余章节中与之冲突的条款。

| 项目 | 决定 |
| --- | --- |
| 界面 | 一个窗口：登录、连接按钮、线路、套餐。规则/全局、更新、上报问题、修复、退出登录放进设置；删除侧边栏、同步状态卡、主题与关闭行为选项、手动刷新、“测试前 10 项”。错误显示一句人话和一个下一步按钮 |
| 连接判定 | 经节点的 TCP 和 DNS 通过即视为已连接；UDP、IPv6 只记录，不再作为门槛（大量可用节点没有 IPv6 或未开 UDP） |
| 节点 | 过滤面板展示用条目（官网、备用、剩余流量、到期等）和 🇨🇳 回国节点；按国旗识别地区并分组；打开列表时测全部节点 |
| 自动选择 | 由 Xray observatory + leastPing 负载均衡完成（每 5 分钟测速，节点失效自动切换），客户端测速只决定初始节点 |
| 分流 | 照运营方 Mihomo 模版（~/dev/rules/custom.clash.yaml），由 v2fly geosite/geoip 生成有序分段：私有直连、广告拦截、海外服务国内节点直连、AI、Telegram/YouTube/Netflix 代理、Steam 直连、GitHub/Google/Microsoft 代理、Apple/iCloud/B 站直连、娱乐代理、国内直连、国外代理、.cn 直连、国内与私有 IP 直连，其余代理。广告拦截默认开启 |
| AI | AI 域名只走 AI 服务接受的地区（非港澳、非大陆）：用户节点合格就用它，否则自动走最快的合格节点。全局模式同样适用 |
| DNS | 每个分段配一个解析服务器，按分段顺序匹配：直连段用国内 DoH，其余用境外 DoH 并经代理发出 |
| 缓存 | 面板 API 不可达时，上次完整同步最多可用 7 天（原 24 小时），仍受套餐到期约束 |
| 端点 | 自建 Go 服务（server/）取代 Cloudflare Worker，单独机器和域名，可配多个备用域名；规则与更新包下载在主域名失败时换备用域名 |
| 遥测 | 默认开启，带用户邮箱：连接结果与失败步骤、错误码、面板域名可达性、版本与系统。“上报问题”附网络自检并返回 6 位问题编号。不收集访问记录、DNS 查询、流量、令牌、订阅链接和节点凭据（取代第 2 章“日志默认不上传”） |
| 签名 | 暂无 Windows / Apple 代码签名；下载页给出首次打开的操作说明 |
| 启动后自动连接 | 记住用户上次的状态：退出时已连接，下次启动自动连接 |

## 0. 本次修订的决定

| 争议点 | v2 的确定决定 | 理由 |
| --- | --- | --- |
| 启动强制刷新 | 每次启动必须尝试；临时失败后允许仍有效的缓存 | 保留刷新义务，同时避免控制 API 短暂故障导致已有用户全部不可用 |
| 缓存期限 | 最后完整成功同步后最多 24 小时，并受已知到期时间等限制 | 启动与运行期采用同一授权窗口，失败和重启均不能续期 |
| 三平台代理能力 | 所有正式支持目标必须完成 TUN | 防止同一个“全局”按钮在不同平台含义完全不同 |
| API 固定 | 构建固定主备地址和信任范围；远程只能管理已内置的端点 | 明确开发者可改、终端用户不可改；新域名迁移另列 P1 |
| 网页 | 首版调用系统默认浏览器 | 减少内嵌登录、支付与网站兼容负担 |
| 品牌 | 首版单品牌；生产与测试隔离 | 不把可配置 API 扩大为白标运营平台 |
| 更新 | 普通签名更新 P0；强制升级 P1 | 先交付可靠的检查、下载、安装、恢复链路 |
| 控制面一致性 | 串行同步、本地事务提交；不虚构服务端原子快照 | 诚实限定普通 V2Board 接口能够提供的保证 |
| 网络切换 | 有界临时阻断；失败后恢复原网络 | 明确重连期间行为，同时不实现断开后持续锁网 |
| 完成标准 | 真实面板、实际安装包、真实 TUN 流量、故障恢复均通过 | UI 演示和编译成功不能替代交付 |

## 1. 产品目标与范围

### 1.1 产品目标

为普通用户提供一个运营方专用桌面客户端。用户安装后登录账号，在首页连接或断开，只需理解“规则 / 全局”和节点选择。系统自动处理核心、订阅、分流、权限、API 故障切换及版本更新。

必须满足：

1. 使用 Wails v3 + Go 实现桌面应用，保留 React + TypeScript 界面，使用 Xray-core 承担代理连接与路由。
2. 支持第 3 章列出的 Windows、macOS 和 Linux 目标，逐目标交付安装包。
3. 首页显著展示到期日期、剩余时间、账号状态和续费入口。
4. 每次冷启动尝试同步账号与订阅，运行期间定时刷新，并响应网络恢复、唤醒和续费返回。
5. 支持主备 API、受控远程策略、规则资源发布及普通客户端更新。
6. 用户不需要复制订阅、填写 API、下载核心、编辑配置或执行命令。
7. 客户端内的官网、续费、帮助按钮直接打开系统浏览器。
8. 开发者通过集中构建配置更换 API 与发布环境；正式安装包固定这些信任边界。

框架替换属于工程变更，须记录它如何满足相同的平台、权限、更新及验收要求。不能擅自替换 Xray 核心或减少正式支持平台。

### 1.2 P0 与 P1

| 能力 | P0 首版 | P1 后续 |
| --- | --- | --- |
| 用户操作 | 登录、连接/断开、规则/全局、自动/手动节点 | 多账号聚合、通用订阅导入 |
| 平台网络 | 支持矩阵内的 TUN、DNS、UDP、IPv6 明确处理 | 系统代理兼容方式、更多系统与架构 |
| API | 一个目标面板适配器、包内主备、自动故障切换 | 任意面板兼容、签名授权的新域名在线迁移 |
| 订阅 | 一种冻结的目标格式、规定的协议组合、自动同步 | 新协议、新传输、新格式 |
| 远程运营 | 受限参数、公告、链接、规则、端点排序、节点运营标记 | 任意插件、脚本或代码下发不在路线范围内 |
| 更新 | 检查、下载、验证、用户确认安装、故障恢复 | 强制升级、核心独立升级 |
| 网页 | 系统浏览器、续费账号提示、返回刷新 | 隔离内嵌网页、单次网页登录交接 |
| 发布 | 单品牌、生产/测试隔离、命令行发布工具 | 白标平台、多品牌并行管理、图形运营后台 |
| 安装格式 | Windows NSIS；macOS DMG + 更新 ZIP；Linux DEB | AppImage、RPM、便携版、商店发行 |
| 语言 | 简体中文 | 多语言 |

P1 不计入首版完成率或必过验收。若开发期间新增 P1，必须同步增加范围、测试与发布说明。

### 1.3 明确不做

- 移动端、路由器、无桌面 Linux 服务器。
- 原生支付、购物车、复杂订单管理；通过运营网站完成。
- 用户自定义路由、DNS、端口、核心配置和信任域名。
- 与其他 VPN 同时接管全机网络的保证。
- 断开或退出后持续阻断全机联网的 Kill Switch。
- 远程执行任意脚本、命令、动态插件或任意 Xray JSON。
- 未验证的“所有 Linux”“所有 V2Board 分支”“所有 Xray 协议”。

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| 规则 / 全局 | 流量进入 Xray 后的路由模式 |
| TUN | 系统流量进入核心的接管机制，不是第三个首页模式 |
| API 端点 | 登录、账户、订阅描述等控制服务入口 |
| 订阅源 | 返回节点或连接参数的服务，可能与 API 不同域 |
| 代理节点 | 承载用户数据流量的 Xray 出站服务 |
| 完整同步 | 本轮读取账号与节点，完成校验并在本地一致提交 |
| 账号轮询 | 单独更新账号显示与限制，不延长旧节点有效期 |
| 临时故障 | 离线、超时、临时服务器错误、无效响应等，不能证明授权被撤销 |
| 明确限制 | 适配器已确认的到期、封禁、无套餐、流量耗尽或节点撤销 |
| 强制刷新 | 启动必须发起一次有期限的同步尝试，不代表必须成功才可使用有效缓存 |
| 强制升级 | 通过版本门禁阻止旧版使用；首版不实现 |

## 2. 默认行为与参数

以下是本版确定的默认值。远程配置只能调整表中允许的范围；本地硬限制不能远程突破。

| 项目 | 默认值 | 远程边界 |
| --- | --- | --- |
| 默认模式 | 规则 | 只能设置新用户的初始值，不能反复覆盖用户已选模式 |
| 默认节点 | 自动选择 | 可调整推荐和候选资格，不能扩大服务端授权 |
| 开机启动 | 关闭 | 用户偏好，远程不能强制开启 |
| 启动后自动连接 | 关闭 | 用户开启后仍受同步与授权门禁约束 |
| 关闭窗口 | 有可用托盘时最小化到托盘，首次说明 | 无可靠托盘时显示退出确认，不隐藏失联 |
| 冷启动同步 | 必须尝试，临时失败允许有效缓存 | 不能关闭启动尝试；不能用策略凭空延长旧缓存 |
| 完整同步周期 | 1,800 秒，±10% 抖动 | 300–21,600 秒 |
| 账号轮询周期 | 300 秒，±10% 抖动 | 60–3,600 秒，且不大于完整同步周期 |
| 公共策略检查 | 900 秒，±10% 抖动 | 300–3,600 秒 |
| 更新检查 | 启动后及每 21,600 秒 | 3,600–86,400 秒；用户可手动检查 |
| 有效缓存上限 | 完整同步完成起最多 86,400 秒 | 600–86,400 秒，可收紧；已有截止时间不因放宽自动后移 |
| 单次网络请求 | 建连 3 秒、请求总计 6 秒 | 仅可在已实现的合理范围内收紧；全局预算优先 |
| 启动控制面网络预算 | 20 秒 | 固定上限，所有重试共享 |
| 本地订阅解析 | 最长 3 秒 | 不可提高 |
| 核心配置预检 | 最长 5 秒 | 不可提高 |
| 一次网络切换事务 | 正常调度条件下最多 15 秒，包含清理 | 不可提高，重试不能重新计时 |
| 同步失败退避 | 30 秒、60 秒、120 秒，之后最多 5 分钟，带抖动 | 尊重服务端更长的 Retry-After |
| API 粘性 | 健康端点 10 分钟 | 端点被禁用时不适用 |
| API 熔断 | 连续 3 次传输失败，首次 60 秒，上限 5 分钟 | 业务拒绝不计作可绕过故障 |
| 到期提醒 | 7 天、3 天，24 小时内显示小时 | 阈值可改，首页到期信息不能隐藏 |
| 自动探测 | 最多 3 个候选，并发不超过 2 | 手动列表探测最多 10 项/批，并发最多 4 |
| 自动下载更新 | 确认非计费网络且非低电量时开启 | 网络属性未知、计费网络或电量低于 20% 且未充电时需用户选择 |
| 自动安装更新 | 关闭 | P0 必须由用户触发；不能暗中中断连接 |
| 日志 | 本地脱敏，默认不上传 | 远程不能开启访问记录或秘密采集 |

参数校验必须满足：

- 完整同步周期 × 1.1 + 20 秒 + 60 秒裕量，小于允许的缓存时长。
- 已知套餐到期或缓存截止早于下次轮询时，提前触发刷新，并独立设置截止处理。
- 任何刷新失败、账号单独成功、读取同版策略、点击按钮或重启，都不能刷新完整同步成功时间。
- 不能因远程值越界而悄悄“猜一个近似值”；拒绝不合法配置并保留此前有效配置。

## 3. 平台、安装与支持承诺

### 3.1 首版矩阵

| 目标 | 架构 | 安装形式 | 安装及网络权限 | 必过能力 |
| --- | --- | --- | --- | --- |
| Windows 10 1809（build 17763）及以上、Windows 11 | x64 | 签名 NSIS，机器级安装 | 安装/更新服务时 UAC；普通 UI 不提权 | TUN、DNS、TCP/UDP、恢复、升级、卸载 |
| macOS 14 及以上、且被锁定依赖实际支持的系统版本 | arm64 | 签名、公证 DMG，更新 ZIP | 应用位于 /Applications；首次网络辅助服务授权 | 同上 |
| macOS 同一系统范围 | x64 | 独立签名、公证 DMG，更新 ZIP | 同上 | 同上 |
| Ubuntu 24.04 LTS，GNOME | x64 | DEB | 系统包管理器/Polkit 安装辅助服务 | 同上 |

“macOS 14+”不是对未来尚未测试系统的自动支持承诺。每次发布维护 support-matrix.json，列出实际验证的系统版本、内核/桌面环境、架构、包格式、依赖版本和测试结果。未通过的目标不得上架为正式支持；如不能交付表中某目标，必须作为范围变更说明，不能用仅能打开 UI 的包代替。

不承诺 Windows 10、Windows ARM64、Linux ARM64、其他 Linux 桌面和发行版。首版不提供无需管理员权限的完整 TUN 模式。

### 3.2 安装体验

1. 安装包包含正确架构的应用、Xray、必要平台组件及基础规则资源。
2. 用户无需手动下载核心、导入配置或配置代理。
3. 系统授权只在安装、首次启用服务、服务升级或必要修复时出现；日常切换节点不重复弹出。
4. 拒绝授权后仍可登录、看到账户信息、打开网站、检查更新；连接按钮说明需要网络权限并提供重试。
5. 首版采用机器级网络服务、每用户独立账号数据。多系统用户不能同时拥有网络接管权。
6. 不要求关闭系统安全功能或禁用证书校验；不承诺所有系统都完全没有安全提示。
7. 卸载停止核心和服务、移除本项目安装资源、恢复属于本项目的网络改动；账号数据删除提供明确选项。
8. “恢复原网络”是撤销本应用的改动，保留用户或其他软件后来合法改变的设置，不等于强行改为固定 DNS 或清空所有代理。

### 3.3 技术依据

Xray 当前官方文档已包含 Windows、Linux、macOS 的原生 TUN，但自动路由、防环路及 DNS 的平台行为不同。选定的实际 Xray 版本必须逐平台验证，不能假设相同配置可以覆盖所有平台。[S1]

更新由 Go 桌面控制器与原生 helper 协作完成。macOS 签名及更新 ZIP、Linux 包管理权限与辅助服务更新必须落实到实际安装包测试；不依赖 Electron 更新器。

## 4. 用户旅程与界面

### 4.1 首次使用

下载匹配平台的安装包 → 安装并授权必要服务 → 登录 → 自动同步 → 显示到期信息 → 点击“连接”。

首次模式为规则，节点为自动选择。成功判据是核心已启动、网络接管完成且经所选出站的探测成功，不能仅凭进程存在显示“已连接”。

### 4.2 首页

首页首屏固定出现：

- 一个主要的连接/断开按钮。
- 可读连接状态及当前实际节点。
- 规则 / 全局两个选项。
- 节点选择入口。
- 显著的套餐到期卡片、剩余时间、续费按钮。
- 当前登录账号的脱敏标识。
- 同步失败或使用缓存时的轻量提示及最近完整同步时间。

更新提示、公告和推荐信息不能遮住主要操作。不得远程隐藏到期、断开、退出账号、帮助和错误恢复入口。

### 4.3 节点抽屉与设置

节点抽屉包含自动选择、分组、搜索、名称、兼容性及延迟状态。显示“未测试 / 测试中 / 超时 / 不兼容”，不能用固定假延迟代替结果。

设置只保留：开机启动、启动后自动连接、关闭窗口行为、主题、检查更新、诊断、退出账号。所有工程参数留在内部。

有可靠托盘时，关闭窗口默认留在后台，首次显示一次说明；没有托盘时，关闭动作必须让用户明确选择是否退出。“退出客户端”停止接管并结束任务。开机启动与启动后自动连接是两个独立设置。

### 4.4 操作结果

| 场景 | 用户看到的结果 |
| --- | --- |
| 同步成功 | 更新节点和到期信息，可连接 |
| 临时故障但缓存有效 | “暂时无法同步，使用上次有效数据”，显示剩余可用截止信息 |
| 无缓存或缓存已过期 | 保持首页可操作，提供重试、帮助和网页入口 |
| 明确到期/流量耗尽/封禁 | 原因与恢复入口准确，不统一写“网络错误” |
| 手动节点失效 | 明确提示重新选节点，不悄悄换地区 |
| 重连失败 | “连接失败，已恢复原网络”，用户可再次连接 |
| 恢复尚未确认 | 显示“正在恢复网络”或“需要修复”，不能先报恢复成功 |
| 更新已准备好 | 用户选择安装时说明会断开代理并重启 |

键盘导航、焦点、文本缩放、亮暗色、长文本布局均须可用；状态不能只靠颜色表达。

## 5. 账号、到期与权益

### 5.1 独立保存业务事实

账号模型不能仅用一个互斥枚举覆盖全部情况。至少保存：

- 登录会话状态：有效、确认失效、未知。
- 服务使用资格：允许、拒绝、未知，以及适配器确认的依据。
- 封禁状态、套餐存在状态、流量是否耗尽。
- 到期类型：有限日期、已确认长期有效、未知。
- 总流量类型：有限、不限、未知；已用字节数。
- 账户标识、套餐名称、流量重置时间、最后读取时间、来源。
- 已观察到的限制及其解除条件。

首页主原因优先级：封禁 → 无套餐/无服务资格 → 已到期 → 流量耗尽 → 信息待验证；其他同时存在的原因可在详情显示。这个优先级只影响展示，不覆盖原始事实。

### 5.2 日期与授权的区别

| 事实组合 | 行为 |
| --- | --- |
| 服务明确允许，到期日期未知 | 可以在有效快照范围内连接；显示“到期时间暂不可用” |
| 服务资格未知，但以前的完整快照仍有效 | 只能按缓存规则使用旧快照 |
| 服务资格未知且无有效快照 | 不建立代理，提示重新同步 |
| 服务标记允许，但明确到期时间已过 | 视为业务矛盾，先阻止新连接并重新验证；不能自行解释为永久 |
| 明确封禁、到期、无套餐或计费流量耗尽 | 停止失效授权连接，不能通过缓存绕过 |
| 已付款但客户端尚未确认 | 显示正在刷新；不根据网页文字提前恢复权限 |

单独账号轮询可施加新的明确限制、更新显示。解除限制、恢复旧节点资格和延长可用窗口必须经过完整同步。

### 5.3 显示与计费合同

- 日期在内部使用 UTC 或声明单位的 Unix 时间，显示本地时区及完整日期；适配器明确秒/毫秒，不运行时猜测。
- null、0、缺失字段不能默认变成“永久有效”或 1970 年。
- “长期有效”与“不限流量”是不同事实。
- 7 天内提醒，3 天内强调，24 小时内显示小时，1 小时内可显示分钟；到期判断使用精确时间而非取整后的天数。
- 计费用量以面板数据为准；核心实时流量不能覆盖账单。
- 字节数用安全整数或十进制字符串处理，避免精度损失。
- 一次跨越提醒阈值只通知一次；同一账号同一到期事件不每次轮询重复弹窗。
- 离线显示必须带最后更新时间，不能假装刚刚确认过。

### 5.4 登录会话失效

确认账号访问凭据失效时：

1. 若目标面板确实提供正式续期能力，最多尝试一次，计入当前同步预算。
2. 续期进行中仅保留原本仍有效的既有代理，不启动新核心、不切换节点。
3. 没有续期能力或续期被明确拒绝时，停止该账户代理，清理无效访问凭据，要求重新登录。
4. 显示“登录已失效”，不能声称套餐到期或永久封禁。
5. 若续期发生临时网络失败，旧凭据仍保持“已确认失效”，另行显示“暂时无法恢复登录”，不能降为普通未知状态。续期结束或本轮网络预算到期仍无有效新凭据时，停止该账户代理，保留可安全重试的续期信息并提供重试/重新登录入口。
6. 同一账号重新登录形成新会话，完整同步成功后正常恢复。

普通网络错误不得推导为登录失效。订阅凭据失效按第 8 章独立处理。注销后清除本账号令牌和节点秘密，不能在下次登录时复活被删除的缓存。

## 6. 架构与责任

| 模块 | 责任 | 边界 |
| --- | --- | --- |
| Renderer | 展示状态、发送有限用户意图 | 不保存密码、API token、订阅 URL 或节点秘密 |
| 主进程协调器 | 登录、同步、连接意图、策略应用、任务取消 | 唯一业务状态写入者 |
| PanelAdapter | 实际 V2Board 请求及语义转换 | 不凭猜测补出服务端能力 |
| SubscriptionParser | 将冻结的输入格式转为内部节点模型 | 不执行输入内容，不直接透传配置 |
| ConfigCompiler | 将节点、模式、资源编译为受限 Xray 配置 | 只使用本地实现过的能力 |
| CoreSupervisor | 核心启停、健康检查、有限恢复 | P0 不开放 Xray 动态管理 API |
| PlatformNetworkService | 特权操作、TUN 资源协调、网络恢复、接管所有权 | 不提供任意 shell、任意文件写入或任意进程启动 |
| PolicyService | 策略验签、版本、时效、资源与发布状态 | 不能扩大构建信任范围 |

默认使用系统 WebView、最小 Command/状态桥接与编入主程序的本地 UI。远程网页首版不进入拥有本地能力的渲染环境；生产应用禁止远程前端与开发调试入口。

UI、主进程、核心、辅助服务分别有生命周期；关闭窗口不等于停止主进程，退出进程必须触发接管清理。第 12 章规定系统级监督失效时的边界。

## 7. V2Board 对接合同与服务端责任

### 7.1 只承诺已冻结的目标部署

P0 适配一个真实 V2Board 部署。api-contract.md 必须记录实际版本/分支、操作名、方法、路径、请求字段、鉴权方式、响应、单位、错误语义、幂等性和脱敏样例。

内部方法至少包括：

| 方法 | 输出 |
| --- | --- |
| login / restoreSession | 不透明会话、账户标识、确实存在的续期能力 |
| fetchAccount | 第 5 章的账号事实 |
| fetchSubscriptionDescriptor | 完整订阅地址、格式、凭据类型、明确等价备用地址 |
| fetchNodes | 完整性结论、规范节点、逐项错误和是否权威空列表 |
| logout | 本地清理；面板确有能力时同时撤销远端会话 |

P0 原生登录基线为邮箱与密码。若实际部署要求验证码、双因素或其他挑战，阶段 0 必须冻结该部署的正式流程并实现；不允许通过忽略校验或禁用服务端保护来满足“简单登录”。通用验证码/SSO 平台不在首版范围内。

注册、找回密码仅在部署支持时显示网页入口。关闭注册的服务不能出现不可用注册按钮。

### 7.2 不得假设

不假设所有 V2Board 使用相同路径、Bearer 前缀、refresh token、服务端 revision、稳定节点 ID、统一订阅格式、可信空列表标记或网页免登录接口。

账号认证信息、订阅 token、节点凭据是不同秘密。官方实现中的账号认证与订阅处理体现了这些差异，订阅格式还可能受 flag / User-Agent 影响，并含用于显示套餐信息的伪节点。适配器必须用目标部署样例确认，不能从节点名称推断到期。[S4][S5]

API 域名与订阅域名可以不同，不能替换 host 拼出所谓备用订阅。[S6]

### 7.3 服务端前提

主备入口必须属于同一账户域、同一授权系统并共享兼容的会话和业务状态。P0 首选多个入口访问同一正确状态的后端，承诺域名/入口故障切换；不把它宣传为数据库或整个机房的灾备。

账户与订阅响应禁止不受控的 CDN 公共缓存。若使用异步副本，部署方须提供能够验证的新鲜度或一致性合同；否则客户端不能保证识别所有陈旧授权。

没有统一服务端 revision 时，客户端只承诺“有期限的一轮新读取 + 本地一致提交”，不承诺服务端原子快照。服务端在读取期间撤销权限可能由后续轮询才能发现；真正的到期、流量和节点权限必须由服务端执行。

### 7.4 客户端与服务端交付分工

| 项目 | 责任 |
| --- | --- |
| 真实面板、测试账号、字段语义、主备共享状态 | 运营方/面板维护方提供 |
| 适配器、字段校验、同步与故障处理 | 客户端开发交付 |
| 策略签名、规则发布、更新清单、发布校验脚本 | 本项目交付 |
| HTTPS API、订阅、网站、对象存储/CDN、证书与密钥保管 | 运营方部署与维护 |
| 面板缺失的权威空列表/一致性/网页登录交接能力 | 如确需，另列明确的服务端扩展；不得假装原版自带 |
| 完整图形运营后台 | P1 |

首版无需重写 V2Board。对于无法表达的空订阅语义，默认采用第 9 章的保守处理；如果业务要求立即确认空授权，则必须提供相应服务端合同。

## 8. 构建固定 API、主备与引导网络

### 8.1 构建固定的含义

集中构建配置包含产品标识、环境、渠道、适配器、主备 API 的 ID 与完整 base URL、策略源、订阅可信来源、网页链接来源、更新源、验签公钥及硬限制。

正式安装包：

- 不提供 API 输入框，不接受命令行、用户配置或环境变量覆盖生产端点。
- 远程策略只能调整包内端点 ID 的排序与临时启停，不能注入新 URL。
- 正常策略至少保留一个 API 端点；全部停服使用有结束时间的维护状态表达。
- 新 API 域名、订阅可信来源、更新信任域或根公钥通过经过签名的新客户端加入。
- 生产与测试使用不同 appId、数据目录、会话、密钥和更新命名空间；测试包不能覆盖生产安装。
- 单品牌不等于代码中写死 URL；更换集中配置即可重新构建，但多品牌并存管理不属于 P0。

API URL 和公钥不是秘密。这里约束正式客户端的配置行为，不承诺抵御本机管理员篡改安装文件。

### 8.2 请求选择与粘性

1. 当前有效策略的排序优先于构建顺序；无有效策略时使用构建顺序。
2. 新安装选当前首选端点；后续优先使用仍启用、健康且在 10 分钟粘性期内的端点。
3. 被禁用的端点立即停止接收新请求，不能因为粘性继续使用。
4. 每一轮完整同步尽量固定同一 API 入口。中途切换时丢弃尚未提交的正向候选，在剩余预算内重新取得必要数据。
5. 已生效的明确限制不能因这一轮切换而撤回。
6. 粘性结束后，在下一轮同步边界尝试当前排序首选；不为切回而打断正在执行的登录写请求。
7. 端点恢复不触发代理节点切换；代理节点失效也不随机切 API。
8. 对同一逻辑幂等请求，单轮在同一端点最多一次普通传输尝试；账号、描述等不同请求可以共用该入口。正式续期、订阅描述恢复及切换入口后重新取得必要数据是明确的有限流程，仍共享同一预算，不能叠加多层重试。

“主端点”表示当前有效排序的首选项，不永远等于 ID 恰好叫 primary 的项。

### 8.3 错误分类

| 结果 | 自动换 API | 处理 |
| --- | --- | --- |
| DNS、连接失败、超时、连接重置、502/503/504 | 可以，预算内 | 记录传输健康，尝试下一受信端点 |
| TLS 校验失败 | 可以换其他受信端点 | 不关闭验证，不向失败来源发送秘密 |
| 返回 HTML/WAF 或合同不兼容 | 可隔离该入口并有限切换 | 不把 HTTP 200 当成功 |
| 错误账号/错误部署数据 | 拒绝并隔离 | 不污染缓存，记录合同故障 |
| 密码、验证码、双因素错误 | 不可以 | 提示用户；不跨域重复提交 |
| 账号会话失效 | 不用于绕过 | 按第 5.4 节处理 |
| 到期、封禁、无套餐、流量耗尽 | 不可以 | 更新业务限制 |
| 429 | 不可以绕过限流 | 遵守 Retry-After 和服务级退避 |
| 订阅源 401/403 | 不直接等同账号会话失效 | 依据订阅合同重新取得描述一次 |

登录等非幂等请求只有在确定尚未发送，或服务端明确支持幂等键时，才自动换端点重试。已经发送但结果未知时提示用户重试，不能悄悄重复创建会话或订单。

### 8.4 订阅源与备用地址

可信订阅 origin 是安全边界，不是可替换域名表。

优先使用当前订阅描述返回的完整 URL。仅当适配器合同或构建配置声明两个完整入口具有同一账号、同一订阅和兼容凭据语义时，才允许备用下载。不得用字符串替换 API host、复制任意查询 token 或盲目跟随跨域跳转。

订阅凭据明确失效时，在账号会话仍可用的前提下重新获取描述一次，并重试一次下载；所有步骤共享当前 20 秒预算。失败后显示订阅错误，不能无依据注销账号。

若只是凭据轮换失败、下载不可达或错误语义未知，且没有明确业务撤销，可在原截止内使用此前有效快照；不延长期限。若适配器确认该错误表示订阅/节点使用权限已撤销，则停止相应代理并禁止旧快照放行，但不误报账号密码失效。

### 8.5 引导连通性

未建立代理时，至少一条完整引导路径必须能直接访问：

- 登录、会话验证、账号和订阅描述。
- 实际订阅下载与必需重定向。
- 目标登录流程必需的验证码/验证服务。
- 已启用能力必需的资源。
- 帮助、续费、策略和更新的独立入口应尽可能可直达；普通策略暂时不可达可使用内置基线。

控制客户端使用显式网络路径，不能被失效的系统代理环境变量困住。可选的“经已连接代理重试”只能使用仍有效的现有会话，P0 不以它代替冷启动直达条件。

域名、CDN、证书、DNS 和后端故障域在部署清单中分别记录。两个域名指向同一源站只提供入口冗余，不能声称源站灾备。

## 9. 节点模型、协议与自动选择

### 9.1 P0 协议范围

首版实现并测试以下组合，发行清单记录实际版本和测试配置；下发节点还必须符合目标部署合同。

| 协议 | P0 传输与安全组合 | 其他组合 |
| --- | --- | --- |
| VLESS | TCP + TLS；TCP + REALITY；flow 仅采用冻结版本验证通过的空值或 xtls-rprx-vision | WS、gRPC、XHTTP 等另列 P1 |
| VMess | AEAD，WebSocket + TLS | 旧 alterId 方式及其他传输 P1 |
| Trojan | TCP + TLS | WS、gRPC 等 P1 |
| Shadowsocks | TCP/UDP，chacha20-ietf-poly1305、aes-128-gcm、aes-256-gcm | 2022 系列及其他加密方法 P1 |

上述表是本项目的实现范围，不是宣称已经测试通过。阶段 0 必须锁定 Xray 版本并验证组合。无法支持的字段必须明确拒绝，不降低 TLS 验证、不默默删除安全参数、不改用其他核心。

P0 只解析一个目标部署实际采用的订阅格式，格式名与版本在 adapter-manifest 中固定。结构化数据、URI/Base64、Clash YAML 不自动互通；若实际格式需要转换，必须经过解析器到内部模型再编译。

### 9.2 节点模型与准入

节点至少包含：nodeId、显示名称、分组、地区标签、排序、规范连接参数、凭据引用、协议能力、来源、连接指纹、兼容状态与最近探测结果。

- 优先使用服务端稳定 ID。
- 没有 ID 时，按确定的连接身份规范生成哈希，排除纯显示名称与排序；地址、凭据或连接身份变化允许视为新节点。
- 同名节点不能互相覆盖；无法可靠映射时按替换处理，不猜测它仍是旧节点。
- 显示属性改变不重连，连接指纹改变触发受控重连。
- 生产可选节点必须使用已验证的协议模板，并由部署方确认 TCP 与 UDP 能力；仅 TCP 或能力未知的节点默认显示不可选及原因。
- P0 支持 IPv4 与双栈网络；节点与出口的实际 IPv6 能力必须在发布及运行测试中记录，不能静默泄漏 IPv6。
- 订阅解码后最大 10 MiB、最多 5,000 条，限制字段长度、嵌套深度和解析时间。
- 伪节点必须通过接口能力、结构化标记或明确输出合同排除，不能简单按“到期/剩余”名称关键词删除真实节点。

### 9.3 四类解析结果

| 结果 | 是否覆盖旧快照 | 行为 |
| --- | --- | --- |
| 整体响应损坏、截断、HTML、超限、身份不匹配 | 否 | 本轮失败，旧快照仅在原有效期内可用 |
| 列表结构完整，部分节点语义错误 | 可以，至少有合法条目且完整性可确认 | 隔离坏节点，合法节点可用，记录逐项原因 |
| 完整列表中所有条目均可识别但不兼容 | 接受当前列表事实，不能当作网络失败 | 不继续使用旧列表假装仍受授权，显示无兼容节点 |
| 已鉴权、业务成功、语义明确的空列表 | 是 | 停用旧节点，显示当前没有可用节点 |

所有条目都损坏时归类为数据错误，不能宣称运营方撤销了全部节点。

部分坏节点可独立隔离，前提是列表结构及枚举完整性可信。若连条目边界、身份或完整性都不能确定，拒绝整轮，不根据“解析剩余项”推断撤销。已知 ID 的新记录本身不可用时，该节点进入隔离，不能让旧参数冒充通过了新验证。

逐项隔离仅随本轮被接受的完整列表提交。整轮拒绝或所有条目损坏时，失败响应中的局部结果不修改当前快照或节点限制，仅记录诊断；旧快照仍按原期限处理。已由账号接口独立确认的业务限制不受此规则影响。

空字节、空 Base64、解析后数量为 0 不是权威空列表的充分证据。目标合同无法表达权威空列表时，默认按未知处理；账户接口明确无服务资格时仍立即停用。

304 只有在当前账号、URL、格式及 ETag 对应的完整缓存存在时才可复用；否则重新获取全量。304 不延长不相关账号或其他订阅的有效期。

### 9.4 自动选择与手动选择

自动选择依次：

1. 过滤无授权、不兼容、运营禁用和未通过能力准入的节点。
2. 同一次运行优先保留当前仍健康节点，不因几毫秒延迟差反复切换。
3. 重新连接时优先尝试最近健康节点，其次是同地区推荐候选；首次连接从运营排序取得候选。
4. 每轮最多探测 3 个节点，并发不超过 2；总探测预算 6 秒。
5. 全部同地区候选失败时，自动模式允许按运营排序跨地区，首页必须显示实际地区变化。
6. 无地区元数据时按推荐排序，不能凭节点名称猜地区。
7. 候选仍失败则结束本轮，允许用户重试或手动选择，不后台扫描 5,000 个节点。

手动选择失败时保留用户选择并停止，不静默换地区。当前手动节点被权威移除时停止并提示重新选择；自动模式可在同一有界恢复事务中切换合法候选。

运营标记分别为：

- hiddenFromList：只影响普通列表展示；当前使用项仍显示，避免看不见自己连接的节点。
- eligibleForAuto：只影响自动候选，不取消手动选择权限。
- disabledForConnection：在当前有效运营策略期间禁止新连接并处理当前连接。
- 服务端授权撤销：属于业务事实，不因运营策略到期而自动解除。

首版不把 hiddenFromList 推导为不可用，也不把临时运营禁用当作永久安全撤销机制。

当前手动节点被运营禁用时断开并清除自动重连意图；自动模式可以在同一有界事务内切换其他合法节点。没有合格替代或恢复失败时结束连接尝试，等待用户操作。

### 9.5 健康探测

- 至少两个不同故障域的小响应 HTTPS 测试目标，地址在构建信任范围内，响应内容或状态有明确验证方式。
- 检查必须强制经过所选节点出站，不能被规则模式的直连规则命中。
- 不只测 TCP 端口或 ICMP；发布测试还需验证 UDP 和 DNS 实际路径。
- 单目标失败不立即宣判节点故障；先验证另一目标。
- 多节点同一测试目标失败时，将测试服务故障单独显示，不能无限换节点。
- P0 不开放 Xray 管理 API。若使用本地健康探测代理入口，绑定回环地址、使用随机会话凭据、限制用途与生命周期。
- 手动列表测试最多 10 项/批、并发最多 4，30 秒冷却；只在用户请求时继续后续批次。
- 探测只发送随机请求标识与最小必要信息，不上传账号、订阅或节点秘密。

第 9.4 节的候选预探测属于无 TUN、无系统网络改动的准备任务，可使用隔离的临时探测实例。它受 6 秒总预算和候选数限制，结束/取消后清理监听与子进程，不与正式核心争抢接管资源。第 12 章的两次核心启动限制只计算正式网络事务中的接管核心；该事务内的最终健康验证必须计入 15 秒。

## 10. 启动、定时刷新、时间与一致性

### 10.1 启动顺序与预算

1. 打开本地界面，检查并清理本应用遗留的网络接管。
2. 读取当前系统用户的会话、快照、策略、期限与用户偏好。
3. 无可用会话则进入登录；公共策略和普通更新可独立检查。
4. 有会话后启动本轮控制面操作，发起账号、描述及订阅读取。
5. 同时检查公共策略；最多等待 3 秒的首次策略检查，之后使用已验证缓存或内置基线，不让策略下载无限阻塞。
6. 本轮成功则本地提交；临时失败则检查有效缓存；明确拒绝则处理限制。
7. 只有连接门禁通过，才接受用户连接或执行用户已开启的启动自动连接。

20 秒从首次控制面网络请求开始计时，包含续期、主备切换、账号与描述、订阅及一次描述恢复。到期取消尚未完成网络工作，进入同步成功、有效缓存、重新登录、明确无权限或无法连接中的确定结果。

20 秒是网络结果期限，不是所有公网条件下保证同步成功的承诺。用户输入、系统授权、安装修复不计入；也不能在这些等待期间提前阻断网络。解析最长 3 秒、核心预检最长 5 秒，分别可取消、有明确状态；不能借“本地步骤不算网络”无限挂起。

系统已确认离线时，本轮尝试可立即以离线失败结束，不必故意等满 20 秒。必须记录本次已尝试及失败原因，不能在未尝试时直接自动连接。

普通更新检查不占用这 20 秒，不阻塞连接。已接受的新策略必须在实际连接提交前参与门禁；稍后才到达的策略按其生效规则处理，不能声称客户端提前知道它。

### 10.2 有效缓存规则

缓存资格同时满足：

- 属于当前产品、环境、账号、适配器，以及能够从安全存储恢复、此前有效且未被确认失效的同一登录会话；本次仅因临时网络故障无法重新验证，不单独取消缓存资格。
- 曾经成功完成账号与节点的完整同步。
- 本次启动已完成规定尝试。
- 未观察到会话确认失效、明确业务限制、权威空列表或相关节点撤销。
- 当前时间可信程度足以做保守判断。
- 未超过已保存的快照截止时间及已知套餐到期时间。
- 当前节点、规则、平台权限及用户意图仍满足连接条件。

快照初始截止时间：

> 完整同步完成时间 + 当时允许的缓存时长，与已知账号到期及其他明确业务有效期取最早值。

默认最多 24 小时。远程收紧或新账号事实可以提前截止；重新启用较宽默认、策略过期、仅账号成功或重复读取同一策略都不能延长已有截止。延长只能依赖新的完整成功同步。

启动和运行期共享此窗口，无额外叠加的“启动 24 小时 + 运行 24 小时”。

| 使用有效缓存时的操作 | P0 行为 |
| --- | --- |
| 维持现有连接 | 允许 |
| 核心故障恢复、用户重新连接 | 允许，仍受有界恢复和用户意图约束 |
| 切换规则/全局 | 允许 |
| 切换该快照内仍有效节点 | 允许 |
| 增加新账号、新节点、延长套餐 | 不允许 |
| 恢复已经确认撤销的节点 | 不允许 |
| 已知期限到达 | 立即停止依赖该快照的代理，不能等下一次轮询 |
| 用户主动断开 | 保持断开，后台刷新不能自行重连 |

### 10.3 同步协调器

每个登录会话只有一个串行控制面协调器。账号轮询、完整同步、手动刷新、网络恢复和续费返回不并发；重复请求合并。

- 完整同步包含本轮账号读取，合并同时到期的账号轮询。
- sessionGeneration 在登录、注销、切换账号时变化。
- opSeq 在控制面操作开始时递增；取消后的旧响应不论是允许还是拒绝，都不得生效。
- policyGeneration 在影响门禁或核心配置的策略变化时递增。
- connectionGeneration / desiredConnected 保证用户断开、退出和更新安装后迟到任务不能重连。
- 正向数据提交和网络连接提交分别检查当前会话、操作、策略与用户意图。
- 策略变化导致候选配置过时，重新编译或取消，不能启动旧候选。

本地序号只解决客户端并发，ETag / 哈希只标识内容，均不能证明后端数据的业务新旧。有服务端 revision 时按已冻结的作用域和比较规则使用；没有时不伪造该能力。

sessionGeneration 随可恢复登录凭据元数据持久化，正常重启恢复同一逻辑会话时保留；重新登录、注销或切换账号时变更。opSeq 只用于当前进程内请求排序，磁盘中的历史值不参与跨进程新旧比较。恢复缓存不产生新的授权起点。

### 10.4 本地提交与限制

完整同步流程：本轮账户及描述 → 必要订阅 → 解析与身份检查 → 当前策略和能力校验 → 本地事务提交。

账号已明确无权限时立即施加限制，不为完成形式上的节点下载而继续等待。账号成功但节点失败，账号展示与新限制可更新，完整同步时间不变。节点成功但账号失败，不扩大权限、不提交新的可用组合。

解除到期、解封、流量重置、续费和节点恢复都经过完整同步。新账号、节点与相关凭据必须以一致组合落盘；写盘失败不能产生半新半旧的可用快照。

连接失败不等于账号快照无效。合法节点因当前网络不可达，保留合法数据并显示连接失败；不能为了恢复旧连接把已撤销节点重新加入。

### 10.5 定时与生命周期

- 使用单调计时调度，每个任务只能有一个活动实例。
- 网络变更防抖 2 秒，恢复后合并必要同步，不集中补跑休眠期间每一次错过的任务。
- 唤醒时先检查已有期限、过渡保护事务及核心状态；已知到期必须先停止或保持阻断相应接管，再做可延后的网络刷新。
- 进程正常运行时，期限到达不晚于 1 秒调度误差开始停止；恢复完成按第 12 章预算。
- 睡眠期间无法执行用户态处理；唤醒后的第一轮可执行调度必须先检查期限。不得宣称用户态实现保证唤醒前绝无任何数据包。
- 托盘运行继续同步，退出后不另设后台代理维持账号使用。
- 手动刷新有 10 秒冷却；429 的更长限制优先。
- 下次同步时间须早于有效截止，期限附近不能只依靠一个可能被抖动延后的普通定时器。

### 10.6 时间可信度

保存原始到期字段、单位语义、完整同步时刻、可靠的服务端时间参考（如果目标接口确实提供）、本地 UTC、最近时间上界、已确定截止及记录版本。

运行期间使用单调计时计算已经消耗的窗口；需要覆盖睡眠的计时方式由平台层验证。冷启动不能重置起点。检测明显回拨（默认超过 2 分钟）、记录损坏或来源矛盾时，禁止离线缓存放行，要求在线校验或修正时钟。较小时间差也不能使已保存的期限后移。

服务端时间可以来自已确认语义的响应体或源站时间；不把任意 CDN Date 当作不可篡改授权。接口没有可靠时间字段时，按正常本地时钟进行保守判断并记录局限。

本项目防止正常重启、失败重试和可识别时钟异常意外延长授权，不保证抵抗本机管理员修改程序、存储或系统时间。服务端仍是实际授权执行方。

## 11. 规则、全局、DNS、UDP 与 IPv6

### 11.1 两种模式的确定语义

默认规则模板面向主要访问中国大陆及海外服务的用户，ID 为 cn-direct-default-proxy-v1；它是产品初始规则选择，不从用户 IP 推断地区。后续可签名发布同样受限的其他规则模板。

优先级从高到低：

1. 必要的核心出站、引导与网络恢复内部例外，防止接管回环。
2. 普通 DNS 处理规则。
3. 明确的恶意/禁用目标规则（若发布包包含）。
4. 本地回环与规定的局域网访问例外。
5. 签名规则包中的直连/代理规则。
6. 未命中目标走所选代理节点。

全局模式跳过第 5 项的普通地区分流，普通公网业务都走所选节点；保留核心引导、DNS、回环和必要局域网例外。界面说明“全局代理公网流量，保留系统必要例外”，不承诺每个系统数据包都会离机代理。

### 11.2 局域网边界

LAN 例外以冻结规则明确列出，包括回环、RFC1918 私网、链路本地、IPv6 ULA/链路本地及实际本地子网；不能笼统把全部特殊地址或整个运营商地址段自动放行。

普通 UDP/TCP 53 DNS 的接管优先于宽泛 LAN 直连，防止默认网关 DNS 无条件绕行。本地设备发现如 mDNS 采用独立例外和实测清单，不把所有组播或所有 DNS 一起放开。

本机其他 VPN 或企业网络与这些规则冲突时，提示并拒绝无法验证的接管，不覆盖第三方规则。

### 11.3 DNS 模板

P0 不启用 FakeDNS。部署方提供两个经过确认的解析配置：引导/直连解析与代理解析，地址、证书名称及访问路径在构建默认和签名资源范围内。

- 节点域名与必要控制域名使用避免回环的引导路径；解析结果不能自动扩展凭据接收域名。
- 普通应用 UDP/TCP 53 DNS 进入本项目 DNS 处理。
- 已明确直连域名可用直连解析器；代理域名与未知域名默认通过所选节点访问代理解析器。
- 规则资源可使用域名和 IP 分类；域名不可识别时按 IP 规则及最终代理兜底。
- 无法安全取得域名、加密 SNI、应用自带 DoH/DoQ 等，不声称能解密或完整还原；其承载连接按普通业务路由。
- 代理解析失败不能静默改用任意公网直连 DNS。引导失败显示错误，按有界恢复处理。
- 解析器地址、真实请求路径、DNS 失败行为及原系统配置恢复均须抓包验证。

Xray 路由按规则匹配及默认出站工作，因此编译器必须明确顺序和兜底，不能依赖数组偶然排列。[S7]

### 11.4 UDP 与 IPv6

P0 的正式能力为 IPv4、双栈、TCP 和 UDP。IPv6-only / NAT64 为 P1。

发布前验证各平台的双栈路由、DNS、防环路和实际出站。运行环境无法正确接管当前启用的 IPv6 时，拒绝连接并说明，不能悄悄让 IPv6 直连或把未实现的处理称为全局。

节点侧 UDP 或 IPv6 目标不可达应准确报告为相应能力/目标故障。TCP 健康探测成功不意味着全部能力已验证；运行中发现系统性 UDP 路径失败时标记异常，自动模式可尝试一个合格候选，失败则停止并提示。不得为了“已连接”状态隐藏已知的不完整能力。

## 12. 核心、权限、网络事务与恢复

### 12.1 固定核心与最小接口

锁定 Xray tag、来源、二进制哈希、许可证、平台架构及验证结果。应用、核心和辅助服务属于一个兼容发布集合。

P0 不开放 Xray gRPC 管理 API 或任意配置接口。节点、模式、规则/DNS 的实质变化走受控重启；名称、排序、账号展示及公告变化不重启。

配置检查使用锁定版本支持的校验命令，另设运行健康检查；命令行校验成功不代表 TUN、权限和实际网络成功。[S8][S9]

UI 和主进程普通权限。核心由受保护辅助服务管理；如果平台 TUN 实现需要高权限核心，权限说明必须如实记录，不能宣称整个数据面均低权限运行。

### 12.2 唯一资源责任方

首版默认由辅助服务统筹路由、DNS、物理出口和临时保护，Xray 创建 TUN 并转发数据。阶段 0 核验具体版本的配置能力；若某平台必须使用 Xray 自动管理某类资源，需在平台说明中明确改由 Xray 单独写入，辅助服务仅监督及残留补偿。

| 资源 | 默认实际写入者 | 必须记录 |
| --- | --- | --- |
| TUN 创建设备及关闭 | Xray | 设备名称、句柄/标识、生命周期 |
| 系统路由、物理出口、防环路 | 辅助服务 | 规则 ID、接口身份、网络代际、删除条件 |
| 系统 DNS | 辅助服务 | 原配置方式、接口、所有权 |
| 过渡期流量保护 | 辅助服务 | 事务 ID、开始时间、截止、清理状态 |
| 协议连接与分流 | Xray | 受保护的配置快照及指纹 |
| 恢复日志和整机接管锁 | 辅助服务 | owner、用户会话、版本、状态 |

禁止 Xray 自动配置和辅助服务同时独立写同一种路由/DNS/防火墙资源。平台变更必须有实测责任表，不能仅有方案描述。

### 12.3 一次受控网络事务

准备阶段不新增全机阻断：

1. 完成必要同步与授权判断。
2. 选择合法节点，编译候选配置，检查资源和能力。
3. 辅助服务独立复验 schema、调用者身份、固定核心路径和候选内容。
4. 将候选保存为服务拥有的不可被普通用户替换的快照；不先校验用户文件、随后按原路径重新打开执行。
5. 完成权限交互，取得整机接管锁，保存当前网络配置方式。

然后开始 15 秒事务：

1. 建立过渡保护，允许固定的节点握手、引导 DNS、健康探测和本地 IPC 例外。
2. 停止待替换的旧核心和旧接管资源。
3. 启动候选核心、应用对应网络配置。
4. 经选定出站验证真实连接。
5. 成功则提交 Connected 并撤销过渡保护。
6. 失败先清理新事务部分资源，再恢复原网络；需要恢复旧代理时，旧节点仍必须有效，且不得另开时间预算。

最多使用前 12 秒进行连接尝试，最后至少 3 秒预留正常清理；每个事务至多两次核心启动，预算不足不开始下一次。所有节点尝试和恢复共用同一截止。

15 秒是在支持环境、服务正常调度下的硬门槛，不包括用户权限等待，不保证 helper 被杀、OS 监督失效或睡眠期间仍能执行恢复。这些情况按第 12.5 节单独验证。

过渡保护从本次事务建立成功后开始保证受控窗口内的行为。核心突然故障至检测之间不承诺无缝零直连；P0 不提供持续会话防泄漏或永久 Kill Switch。该边界必须写入用户说明，不能以“全局”一词掩盖。

### 12.4 各状态的流量行为

| 状态 | 行为 |
| --- | --- |
| 未连接、首次同步、等待权限 | 不接管，保持原网络 |
| 已连接时后台同步 | 保持既有有效代理；新明确限制立即处理 |
| Connecting / Reconnecting / Switching | 有界过渡保护，普通业务不绕过未验证代理直连 |
| Connected | 按规则/全局处理流量 |
| 连接事务失败 | 清理接管并恢复原网络；不自动立刻再开一个阻断周期 |
| 用户断开/退出/注销 | 取消候选与重试，尽快恢复原网络 |
| 明确授权到期或撤销 | 停止无效代理，清理接管并提示；不持续锁网 |
| 恢复失败 | 保持准确错误状态，提供一键修复和诊断，不谎报成功 |

已连接状态下的网络变更可触发一次有界恢复。连接准备或网络事务最终失败后清除本次自动重连意图，下一次由用户点击；禁止在同一故障上循环“阻断—恢复—阻断”。维护、会话失效或明确业务限制结束整个代理会话时，也清除重连意图；解除限制只恢复按钮可用。用户主动断开后，任何网络事件都不能自动重连。

### 12.5 异常恢复与所有权

- 核心异常：辅助服务发现后执行一次有界恢复事务；超过限制则恢复原网络。
- 主进程退出/崩溃：辅助服务以 1 秒心跳、连续 3 次丢失作为会话失联依据，停止接管；正常可调度环境下失联确认后 5 秒内完成清理。
- 辅助服务崩溃：由 OS 服务管理机制恢复。服务重新运行后，5 秒内优先清理遗留资源与孤儿核心，再接受连接；单独记录 OS 发现到重启耗时，支持平台测试目标为 10 秒内恢复服务。
- 系统重启：服务先处理恢复日志，不在启动账号同步前恢复旧代理。
- 睡眠唤醒：过期事务不能续租，先清理过期保护并检查授权，再进行网络刷新。
- 启动清理、退出、注销、更新和卸载都使用同一幂等恢复逻辑。

恢复日志记录资源所有者、接口和网络代际。原 DNS 为 DHCP/自动时恢复自动配置，不能把旧网络当时的 DNS IP 写到新网络。删除带本应用标记的资源；共享属性采用比较后恢复，发现第三方已改动时不覆盖，记录并说明。

辅助服务和系统监督均不可运行时，无法承诺自动恢复。安装时必须留下受保护、可离线启动的独立网络恢复入口，至少能在用户授权后清理本应用资源，不依赖桌面 UI 或先下载文件。完整应用修复可随后使用签名安装包。不能要求用户手动删除未知防火墙规则作为常规流程。

### 12.6 本机接口与多用户

- 辅助服务只接受有限 IPC：启动受检配置、停止、状态、恢复、受检升级交接。
- 校验调用者、系统用户、安装路径、版本与消息大小；拒绝任意命令、任意可执行路径、任意文件写入。
- UI 单实例按系统用户管理，整机网络接管采用固定产品族锁；随机安装 ID 只作为 owner 元数据，不能各自创建互不排斥的锁。
- B 用户不能读取 A 用户凭据或控制其代理；有其他 owner 时显示冲突并拒绝接管。
- 锁屏保持连接；系统用户注销停止并恢复。快速切换用户不自动转交控制权。
- TUN 可能影响同机其他用户的网络，因此首版支持单一交互会话持有接管，不承诺多人同时独立代理。

## 13. 远程配置、规则资源与生效规则

### 13.1 三层优先关系

| 层 | 内容 | 修改方式 |
| --- | --- | --- |
| 构建信任层 | 端点、来源、公钥、核心能力、系统权限、硬限制 | 签名新版本 |
| 远程策略层 | 已实现功能的参数、运营标记、规则引用、公告、链接 | 运营签名发布 |
| 用户偏好层 | 模式、节点、自动连接、开机启动、主题 | 用户操作 |

先检查构建能力和硬边界，再应用有效策略；策略只能决定未选择用户的默认值，不能反复覆盖已有用户偏好。业务授权由账户和订阅决定，公共策略不能授予额外节点或套餐。

### 13.2 远程允许清单

| 类别 | 可下发 | 应用时机 |
| --- | --- | --- |
| 同步 | 范围内的完整同步、账号、策略间隔及缓存上限 | 调度边界；收紧截止立即计算 |
| API | 包内端点 ID 的顺序、临时禁用 | 新请求边界；禁用立即停止新请求 |
| 节点运营 | 分组、排序、推荐、隐藏、自动候选资格、临时连接禁用 | 展示立即；影响连接时受控切换 |
| 分流 | 已实现模板 ID、签名规则资源、DNS 模板 ID | 下载、校验、编译后受控切换 |
| 首页 | 纯文本公告、到期提醒阈值、流量摘要是否展示 | 验证后 |
| 网站 | 已受信来源内的官网、续费、帮助、客服 HTTPS 链接 | 下次点击 |
| 普通更新 | 检查间隔、非阻塞提示文案 | 下次调度或展示 |
| 维护 | 原因、开始时间、结束时间、适用平台 | 明确时间区间内停止新建并结束代理 |
| 初始偏好 | 新用户默认模式、推荐分组 | 仅在用户尚未作出选择时 |

首版定向范围只有产品、环境、渠道、平台/架构及已声明能力。按用户画像、账号灰度、任意百分比分群为 P1；不得将账号秘密发往公共策略 CDN。

维护最长 24 小时，结束时间不得超过策略 expiresAt；结束后恢复可连接资格，但不强行自动连接。维护不能隐藏帮助、续费和更新。P0 不提供按旧应用版本定向阻断的隐性强制升级。

### 13.3 不允许的下发

任意 JavaScript、shell、插件、可执行文件、Xray 原始配置、脚本路由、webhook、本地路径、任意端口开放、外部 gRPC 管理服务、证书校验关闭、包外 API、根公钥、无限通配域名、访问记录采集、关闭启动刷新、突破缓存硬上限。

新的软件能力必须通过受验证的应用更新发布。远程配置的含义是配置已经实现的能力，不是远程扩展代码。

### 13.4 签名信封与版本

P0 使用 Ed25519，公钥在构建中固定。信封含 keyId、base64url 编码的 UTF-8 JSON payload 和签名。签名覆盖固定用途前缀“v2board-client-policy-v1”及其后分隔换行与原始 payload 字节；算法固定，不由远程选择。

处理顺序：

1. 输入大小上限 256 KiB，检查信封结构。
2. 按内置 keyId 验证签名，禁止由下载内容新增信任根。
3. 解析 JSON，拒绝重复键、不安全整数及不符合 Schema 的字段。
4. 验证产品、环境、渠道、有效期及客户端能力。
5. 验证 policyVersion 与 payload 哈希。
6. 校验参数间关系，保存候选与激活记录，再切换有效策略。
7. 路由资源按第 13.5 节独立下载与激活。

| 版本情况 | 处理 |
| --- | --- |
| 高于已激活版本 | 全部控制字段验证通过后可激活 |
| 相同版本、相同 payload 哈希 | 幂等未变化，不续期、不重弹公告、不重置任务 |
| 相同版本、不同内容 | 拒绝，记录发布冲突 |
| 低于已激活版本 | 拒绝，不能因换镜像或注销重置水位 |
| 签名正确但 Schema/时效/能力错误 | 拒绝候选，不推进激活水位 |

水位按产品、环境、渠道隔离，并包含策略类型；待下载候选和已激活记录分开。只有持久化激活成功才推进对应水位。注销不清除公共水位，应用升级迁移须保留；本地管理员清空全部应用数据不属于不可篡改保证。

回滚内容使用更高 policyVersion 发布。修改 expiresAt 也属于内容变化，必须增加版本并重新签名，不能同版续命。

根公钥轮换通过新签名客户端预置新钥及过渡期。普通配置无权添加根钥。永久紧急安全撤销的独立协议属于 P1；P0 的永久账号/节点撤销由面板授权系统执行。

### 13.5 激活单元与资源

不要把所有资源绑成一个容易被图片或 CDN 文件阻塞的事务。

- 控制策略：端点排序、调度、维护、运营节点标记、纯文本 UI 参数在一个已验证的控制单元内生效。
- 路由资源：精确资源 ID、URL、哈希、长度、版本、有效期与模板能力绑定，独立下载、校验、编译后整体激活。
- 公告 P0 仅纯文本，不下载远程 HTML 或脚本；未来图片失败也不能阻止维护等控制字段。

记录 activePolicyVersion、activeRoutingResourceVersion、pendingRoutingResource 三个事实。控制策略已激活但新规则未就绪时，保留仍有效的旧规则或内置规则，并显示资源待更新；不得谎报整套资源已生效。

资源最大解压后 32 MiB，规则数量和编译时间设定上限并写入 Schema。重定向和下载来源仍受构建白名单约束，按签名哈希命名的资源不可覆盖。同一 ID 不可替换不同字节。

### 13.6 策略失效表

| 内容 | 获取失败/到期时的行为 |
| --- | --- |
| 新策略无效，旧策略仍有效 | 保持旧策略 |
| 公告、推荐、普通排序、临时隐藏 | 到期后回到内置默认 |
| 普通刷新周期与临时端点停用 | 到期回到内置值；不延长已确定缓存截止 |
| 缓存上限曾被收紧 | 当前快照原截止保留；新完整同步可按当前允许值重新确定 |
| 临时维护、临时节点连接禁用 | 在已签名有效区间结束；不能无限粘住 |
| 已确认的账号封禁、到期、节点撤销 | 不因公共策略到期解除；需新的完整业务同步 |
| 远程规则/DNS 资源 | 使用明确的独立有效期，且不得超出授权策略允许区间；到期回到内置规则 |
| 内置规则 | 作为当前安装版本的基线使用 |
| 无法编译任何允许的规则 | 停止接管并给出修复原因 |

回退规则也要执行当前策略检查和受控切换。P0 临时运营禁用不得被运营方当成永久权限撤销；需要永久撤销时必须在面板/节点服务端执行。

### 13.7 HTTP 缓存与发布维护

- 账户、订阅描述及含私密节点内容的响应采用 private / no-store 或经审核的等效策略，禁止公共 CDN 缓存用户数据。
- policy/current、更新索引等可变指针必须重新验证，CDN 最大陈旧窗口 60 秒，404 不长期负缓存。
- 带内容哈希的不可变规则/安装包可长缓存；同 URL 不覆盖不同内容。
- ETag、HTTP 304 只复用对应已验证内容，不延长签名 expiresAt。
- HTTPS 与签名证明来源及完整性，不自动证明它是最新版本。
- 策略默认有效 7 天，运营自动任务至少每日检查并在不足 48 小时前以新版本续签发布；不是只上传一个静态文件后永久无人维护。
- 更新索引默认有效 24 小时，至少每 12 小时发布/续签新序号；监控剩余有效期、镜像一致性和关键产物可达性。
- 私钥留在受控发布环境，不进入客户端、普通仓库或公开对象存储。

## 14. 远程发布与普通自动更新

### 14.1 P0 发布单元

应用、Xray、辅助服务、内置资源作为一个兼容发布集合。普通远程策略不能替换可执行组件。

每个发布目标记录：产品/环境/渠道、OS、架构、包格式、最低 OS、应用版本、核心版本及哈希、辅助协议版本与兼容范围、发布序号、文件大小、下载 URL、SHA-256、平台签名身份。

应用版本使用冻结的语义化版本比较规则，禁止字符串字典序比较。发布索引序号与应用版本独立；索引变新不意味着应用一定升级。

### 14.2 更新信任

- 使用独立的内置更新公钥验证发布索引/清单，平台代码签名与公证仍需通过。
- 不只信任下载 URL 或普通 latest.yml；如果锁定工具没有所需元数据验签能力，实现独立验证层。
- 选用已经发布且验证过的工具版本，不能把 next 文档中的功能当作稳定版现成能力。[S3]
- 索引含 issuedAt、expiresAt、单调 releaseSequence、目标兼容性和撤回列表；同序号同内容幂等，同序号不同内容及更低序号拒绝。
- 主备更新源必须属于同一发布身份，沿用同一序号水位。
- 收到撤回信息后不安装对应产物；解除撤回必须由更高有效序号明确表达。
- 安装前重新确认存在当前有效索引且产物未撤回；无法确认时等待网络，不因普通更新阻止继续使用现有兼容版本。
- 不向更新服务发送账号 token 或订阅秘密，账号到期也能更新。

### 14.3 下载与用户选择

自动检查不打断用户。只有能够确认非计费网络且电量状态允许时默认后台下载；无法判断网络属性时先提示，记忆用户明确选择。下载提供进度、暂停、继续、取消和重试。

安装空间检查至少覆盖下载文件、预计解包、必要备份及 300 MiB 余量；发布清单提供估算并在实际安装时复核。临时下载可保留 7 天供续传；最多保留一个待安装版本和一个恢复所需版本，撤回或不兼容文件及时清理。

用户点击“重启并安装”才执行安装。P0 禁止退出时未经选择自动安装，禁止后台下载完成直接重启。提示会断开代理，并保留稍后选项。

### 14.4 平台安装闭环

| 平台 | P0 必须验证 |
| --- | --- |
| Windows NSIS | 代码签名、机器级安装权限、服务停止/替换、重启后兼容握手、修复安装 |
| macOS DMG + ZIP | 签名、公证、应用更新及辅助服务独立升级交接；不能只验证 .app 替换 |
| Ubuntu DEB | 包签名/清单验证、系统包管理授权与锁、服务脚本、依赖、修复安装 |

electron-updater 处理的应用更新不等于特权服务已经升级。各平台必须有明确的安装事务、固定服务位置、受保护交接和兼容握手；实现方式在阶段 0 通过实机验证后冻结。[S2][S3]

安装顺序：用户确认 → 取消连接任务 → 停止代理并确认网络清理 → 验证产物与安装权限 → 进入平台安装事务 → 校验完整组件集合 → 启动兼容握手 → 成功进入正常 UI。

无法确认网络清理时不继续普通升级；修复路径单独处理，不能让更新进一步破坏现场。

### 14.5 失败与恢复

| 阶段 | 可以承诺的行为 |
| --- | --- |
| 检查/下载失败 | 旧安装未改动，可继续运行 |
| 验签/哈希/平台不匹配 | 拒绝安装，旧安装未改动 |
| 用户安装前取消 | 保留旧安装，清理或保留下载按用户选择 |
| 安装开始后中断、断电、部分替换 | 进入恢复流程，不承诺旧版本完整保留 |
| 应用/核心/helper 不兼容 | 禁止连接，显示修复；不能凑合启动混合版本 |
| GUI 自身无法启动 | 先用安装时保留的离线网络恢复入口恢复联网，再通过已有或官网下载的签名安装包修复；不依赖损坏 GUI |

文件替换不具备跨平台统一原子性。验收要求是最终得到完整兼容集合，或有可操作的恢复安装路径，不是假称永远只能出现完整新/旧版本。

普通运营回退采用更高应用版本号重新发布已知稳定实现。P0 提供修复安装，不实现任意自动降级。数据迁移版本化、失败可识别，必要数据有受保护备份。

### 14.6 强制升级：P1 明确排除

P0 Schema 不接受能阻断连接的 minimumVersion、forceEnabled 或强制 deadline，也不包含这类连接门禁。收到不支持的必需能力时拒绝该策略并保留当前有效配置，不暗中启用未实现功能。

后续启用强制升级前，必须另行实现并验收：

- 按 OS、架构、最低系统、包格式、渠道判断能否升级，不能只看应用版本号。
- 先发布并验证可获取、可安装产物，再发布对应版本门禁。
- 明确限制的是新建客户端代理会话还是终止已有会话；明确 deadline 与宽限，不把“新 TCP 请求”和“新建客户端连接”混为一谈。
- 更新、帮助和续费在门禁期间仍可操作。
- 撤回错误版本时允许以更高策略版本修正或降低最低版本数值，避免无可安装包时锁死。
- 各平台独立演练下载不可用、安装失败、撤回和恢复。

这些条件是 P1 启动门槛，不计入本次 P0 验收。

## 15. 网页、账号一致性与续费返回

### 15.1 首版浏览器行为

官网、续费、帮助、客服、注册和找回密码在系统默认浏览器打开。入口在离线、到期、登录失效、维护和更新状态下仍可点击；实际网页是否可达取决于网络与网站，不承诺任何情况下都成功加载。

只向浏览器交接经过精确解析和白名单检查的 HTTPS URL。拒绝 javascript、file、data、任意本地程序协议和未知 scheme。网站里的支付跳转由浏览器与网站处理；P0 客户端不直接执行任意支付协议。

客户端链接来源与 API/订阅来源分开授权。外部网站子资源由浏览器负责；不能把客户端顶层入口白名单冒充所有网页资源的网络隔离。

### 15.2 续费账号避免混淆

首页续费按钮旁显示当前客户端账号。打开时给出简短提示：“请确认网页中登录的是该账号”。系统浏览器可能已有另一账号登录，客户端不能声称它已同步登录。

目标面板如果提供账号绑定的订单入口，可在正式合同确认后使用短时、限定用途链接；不能把永久 API token、密码或完整订阅 URL 放入 URL、Referrer 或浏览器状态。P0 不依赖该可选接口。

注销客户端只能清理客户端会话，不能宣称已清除系统浏览器的网页登录态。

### 15.3 返回刷新

点击续费入口后进入本地 pendingRenewal 状态，最长 10 分钟：

- 应用下一次重新获得焦点时触发一次完整同步，30 秒冷却，重复事件合并。
- 首页提供“已续费，刷新”按钮，执行相同同步。
- 没有返回焦点事件时，正常周期刷新继续工作。
- pendingRenewal 超时后结束特别跟踪，不永久高频轮询。
- 只有账号 API 与节点同步确认权益变化后才更新可连接资格；网页提示付款成功不作为授权证据。

内嵌网页、网页登录交接及自定义 scheme 回调均为 P1。若实现，必须独立隔离、验证 state 与来源、限制单次凭据并新增验收；不要求 P0 提前交付这些能力。

## 16. 状态、错误、存储与诊断

### 16.1 正交状态

独立维护连接、同步、账号、策略、更新和网络恢复状态。后台更新检查不应把“已连接”变成“更新中”；账号显示可以成功而节点刷新失败。

连接状态至少为：Disconnected、Preparing、Connecting、Connected、Switching、Reconnecting、Disconnecting、RecoveryRequired。同步结果至少为：Fresh、UsingValidCache、NeedsLogin、Denied、Unavailable。

重要状态转换必须记录原因及相关 generation。UI 通过受控数据模型订阅，不从日志或 Xray 进程输出临时拼接业务状态。

### 16.2 错误映射

| 错误码 | 用户文案方向 | 下一步 |
| --- | --- | --- |
| AUTH_INVALID | 登录已失效 | 重新登录 |
| ACCOUNT_EXPIRED | 套餐已到期 | 续费、刷新 |
| ACCOUNT_BANNED | 账号暂不可使用 | 联系支持 |
| QUOTA_EXHAUSTED | 流量已用完 | 查看套餐/重置时间 |
| CONTROL_UNAVAILABLE | 暂时无法同步 | 显示缓存资格、重试、帮助 |
| SNAPSHOT_EXPIRED | 上次数据已超过可用时间 | 在线刷新 |
| SUBSCRIPTION_INVALID | 订阅数据异常 | 重试、诊断 |
| NO_AUTHORIZED_NODES | 当前没有可用节点 | 查看套餐、联系支持 |
| NO_COMPATIBLE_NODES | 当前节点暂不兼容 | 显示兼容说明、更新/帮助 |
| PERMISSION_REQUIRED | 需要系统网络权限 | 重新授权 |
| NETWORK_CONFLICT | 另一会话或软件正在接管网络 | 处理冲突后重试 |
| CONNECT_TIMEOUT | 连接失败，网络已恢复 | 重试、换节点；只在恢复确认后使用该文案 |
| NETWORK_RECOVERY_REQUIRED | 网络恢复未完成 | 一键修复、诊断 |
| UPDATE_DOWNLOAD_FAILED | 更新下载未完成，当前安装未改动 | 重试 |
| UPDATE_VERIFY_FAILED | 更新验证失败，未安装 | 重试、官网 |
| UPDATE_INSTALL_INTERRUPTED | 更新安装中断，需要修复 | 恢复安装 |
| CLOCK_UNTRUSTED | 时间状态异常，暂不能使用离线数据 | 在线校验、检查系统时间 |

错误详情包含阶段、脱敏端点 ID、版本、系统、时间和诊断编号；不得包含完整请求 URL 查询、令牌和节点秘密。

### 16.3 凭据与缓存

使用系统安全存储保护访问凭据和缓存加密密钥；节点秘密不得以可读 JSON 长期落盘。账号/环境隔离，文件权限仅允许相应用户及必要服务。

Linux 可能没有可用的 Secret Service。系统钥匙串后端需要实际核对，不能将不安全回退当成加密保护；钥匙串不可用时，客户端不得把会话秘密保存为明文。

| 状态 | 行为 |
| --- | --- |
| 安全存储可用 | 正常加密保存 |
| 已存在但暂时锁定 | 保留旧密文，提示解锁/重试，不删除凭据、不改写为空 |
| 缺失或后端不安全 | 明确提示仅当前会话有效；秘密只保存在内存，下次需登录 |
| 用户选择临时会话 | 不覆盖之前无法解锁的密文，账号/状态明确区分 |
| 注销 | 清理对应账号令牌、节点秘密与可恢复授权；保留公共策略水位及无敏感偏好 |

无安全存储时，跨重启缓存连接不可用。诊断、日志、崩溃报告、遥测和更新参数均不能包含密码、token、完整订阅 URL、节点私密参数或完整 Xray 配置。

### 16.4 日志与诊断

默认仅记录生命周期、状态、脱敏错误、版本和必要性能数据。本地滚动日志总量默认不超过 20 MiB、保留 7 天。访问域名/目标 IP 清单、完整流量内容不记录。

用户主动导出诊断包时展示内容摘要；本版只生成本地文件，不自动上传。运营远程参数不能开启秘密采集。诊断包必须可用于区分 API 故障、订阅格式错误、节点不可达、权限与网络恢复问题。

### 17.4 连接门禁

建立或切换代理前同时满足：

1. 当前登录会话未被确认失效。
2. 本次启动已尝试同步，且有新的完整快照或仍有效的缓存。
3. 可用快照具有明确的服务允许依据，当前账号没有更严格限制，相关节点未被撤销或隔离；仅“没有看到拒绝”不构成正向授权。
4. 缓存与权益未到期，时间状态足以保守判断。
5. 节点符合当前有效控制策略；路由使用已激活且仍有效的资源，或该策略允许的内置回退，并与核心能力兼容。仅在下载中的新资源不阻塞连接。
6. 平台支持 TUN、必要网络权限已就绪、没有接管冲突。
7. 当前没有有效维护限制。
8. 用户连接意图仍有效，未在注销、退出、更新安装或恢复失败状态。

P0 不包含强制升级门禁或系统代理降级分支。

## 18. 非功能要求与测量

### 18.1 发布硬门槛

- 四个实际发布目标均完成安装、TUN、断开、恢复、更新和卸载。
- 已知授权失效、用户断开和注销不能被迟到任务覆盖。
- 正常可调度条件下，20 秒控制面网络预算、3 秒解析、5 秒预检、15 秒网络事务必须可测且有截止处理。
- 不能静默泄漏 IPv6、绕过 DNS 约定、启动不兼容组件或明文持久化秘密。
- 所有必需错误都能从 UI 到达可操作的恢复路径。
- 一次配置/策略/更新失败不能破坏与该失败无关的有效状态。
- 生产构建拒绝占位域名、公钥和未冻结的部署合同。
- 禁止用模拟成功、只检测进程或只演示 UI 替代真实验证。

### 18.2 优化目标

以下先作为测量与优化目标，不以未经实测的数字承诺全部机器：

| 指标 | 初始目标 | 测量口径 |
| --- | --- | --- |
| 本地首页可交互 | P95 ≤ 2 秒 | 已安装应用冷进程启动，不包含联网与用户授权，30 次 |
| 正常连接耗时 | P95 ≤ 5 秒 | 数据已准备、权限已授予、受控健康节点，30 次 |
| 空闲 CPU | 平均低于一个逻辑核心的 1% | 稳定 10 分钟，无更新下载/探测 |
| 总内存 | 目标 ≤ 400 MiB | 包含 Wails 主程序、系统 WebView 全部关联进程、Xray、helper；按 OS 分别记录 |
| 订阅处理 | 5,000 条范围内保持 UI 响应 | 固定合法样例，解析必须仍满足 3 秒硬上限 |
| 非关键 UI 操作 | 目标 ≤ 100 ms 可见反馈 | 节点抽屉、按钮状态等，不包含网络结果 |

阶段 0 固定基准机器（至少 4 逻辑核、8 GiB 内存、SSD）、OS、依赖、节点和网络条件。Windows 记录 Private Working Set，macOS 记录相应进程物理占用，Linux 优先 PSS；同时保留采样工具与计算方式，不把不同 OS 指标直接当作同一 RSS 数字比较。

性能不达优化目标时解释原因与措施。凡出现无界等待、明显持续泄漏或超过功能期限，按硬门槛处理。

### 18.3 24 小时稳定性

在每个平台至少一个对应架构发布目标完成 24 小时场景测试；macOS 另一架构也须覆盖不少于 8 小时及全部平台关键用例。

24 小时墙钟测试至少包含 22 小时可运行时间、正常周期刷新、每小时 2 次连接/断开、2 次模式切换、4 次节点切换；另包含两次睡眠唤醒、一次网络切换、一次 30 分钟控制面不可用及恢复。使用有效期足够的真实测试账号或有明确标记的受控等价测试服务，真实面板闭环另行完成。

预热 30 分钟后记录趋势；结束前静置 10 分钟再比较。进程数、文件句柄、活动任务不能随操作次数持续累积。无法解释的持续内存增长阻止发布；不能只以起止两个点或 24 小时闲置截图证明稳定。

## 19. 验收计划

### 19.1 执行口径

- P：平台关键用例，在 Windows x64、macOS arm64、macOS x64、Ubuntu x64 四个发行目标分别执行。
- C：共享合同/状态逻辑，使用确定性故障注入测试；四平台另做集成冒烟。
- D：部署与运营用例，必须对真实预发布服务/签名发布链执行。
- UI：界面用例，四个平台检查展示与可操作性。
- 一个用例可以有多种标签；结果不能用其他标签的模拟测试代替。

## 20. 实施阶段、交付物与运营流程

### 阶段 0：四目标技术验证与真实合同

退出条件必须是实际证据：

- 冻结目标面板与脱敏样例、单一订阅格式、协议矩阵、鉴权及期限语义。
- Windows x64、macOS arm64/x64、Ubuntu x64 分别跑通最小原生 TUN、DNS、UDP、双栈、断开恢复。
- 分别验证 15 秒事务保护、helper/核心故障清理及资源唯一写入者。
- 分别完成最小签名应用升级 + helper 兼容交接 + 修复安装。
- 确定依赖版本、签名证书、安装位置、提权机制、性能机器及支持矩阵。

只有设计图、能编译、UI 能启动或“有解决方向”不能通过此阶段。未通过目标明确标红，修复或提出范围变更，不能进入对外正式支持宣传。

### 阶段 1：完整业务闭环

完成真实面板登录、账号、节点、到期显示、规则/全局、选择、启动及周期同步、缓存、主备、外部网页续费。可先在一个平台完成业务整合，但不重新跳过阶段 0 的四目标验证。

退出条件：真实测试账号完成安装后到连接、续费返回、失效与恢复的闭环，关键合同测试通过。

### 阶段 2：平台整合与远程运营

完成四目标 UI/服务集成、网络恢复、策略验签、规则更新、发布脚本、更新事务、诊断及安全存储。

退出条件：四目标安装包可完整运行，普通更新和失败修复通过，运营人员能按文档发布参数和资源。

### 阶段 3：候选发布

执行第 19 章 P0 用例、长时测试、安装升级/卸载、真实引导路径与发布巡检。产物附能力清单和已知限制。

任何未完成的真实面板、证书、平台机器或恢复验证都必须标明，不能以模拟环境代替并宣布“全部完成”。

资料核对日期：2026-10-31。实现阶段必须锁定依赖和实际面板版本；在线主分支和文档会继续变化。下列资料支持技术边界，本文的时间、UI、合同与验收参数是本项目决策。

## 24. 完成定义

以下全部成立才可宣布首版完成：

1. 四个正式目标的安装、登录、真实 TUN、规则/全局、节点选择、到期提示和网页入口均可用。
2. 冷启动必须尝试同步，临时故障容错、期限到达与服务端明确限制按合同执行。
3. 主备 API 不泄漏凭据、不绕过业务限制，不能用不可验证的旧副本假装新授权。
4. 远程策略只能配置已实现能力，具有签名、时效、幂等、资源校验和明确回退。
5. 网络切换、崩溃、睡眠、切网、退出、卸载都具备经过验证的恢复路径。
6. 普通更新覆盖应用、核心、辅助服务集合，安装失败有实际可用的修复入口。
7. 运营方能用交付工具更改构建 API、发布参数/规则/版本、续签、撤回并恢复稳定版本。
8. 第 19 章全部适用 P0 验收通过；P1、缺失的真实资料和未支持的平台明确标识。
9. 配套开发 Prompt 与本文件相同版本、相同默认、相同 P0/P1 边界。

“需求已完成”与“软件已完成”是不同交付。本次文档修订只完成前者。
